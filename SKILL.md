# SCM Context

Все команды — из корня папки скилла (`python` 3.10+, зависимости из `requirements.txt`).
Человекочитаемый вывод — без флагов, машинный (для тебя) — всегда с `--json`.

## Воркфлоу (обязательный порядок)

1. **Обзор, не файл целиком.** Вставленный код/файл сначала через анализ:
   `python chat.py --analyze-file <путь> --json`
   Целая папка — СТРОГО одним вызовом (обход по файлам запрещен):
   `python chat.py --analyze-batch <папка> --json`
   (.java/.py/.md/.txt, до 500 файлов и 5 МБ; `.git/node_modules/build`
   пропускаются). В ответе: итоги (`raw_bytes`, `skeleton_bytes`,
   `skeleton_saving_pct`) + `items[]` по файлам (скелет, методы со связями
   `calls/imports/fields`, фокус-цель) + `text_graph.anchors`
   (привязка текста к коду). Работай по скелету.
2. **Фокус на одну цель.** Для фикса/разбора бери `focus`: тело целевого
   метода + сигнатуры соседей + только его импорты. Поле `focus.context`
   уже собрано и готово к вставке в рассуждение.
3. **Тело по требованию.** Если скелета/соседа не хватило — запроси полный
   текст конкретного метода у пользователя, не подгружай весь файл.
4. **Вопросы по проекту:** `python chat.py [--repo <папка>] --once "<вопрос>" --json`
   Ответ: `hits` (score меньше = ближе), `context` (готовый контекст),
   `saving_pct` (экономия). Долгий первый запуск (~40 c прогрев модели) —
   норма; повторные через сервер (ниже) — миллисекунды.

## Серверный режим (много вопросов подряд)

```bat
python serve.py
python chat.py --remote "<вопрос>"
```

`POST /ask {"query": "...", "ask_ollama": false}` → JSON того же формата
(ключи hits/context/saving_pct), плюс `server_ms`.
`POST /reindex {}` — пересборка индекса. `GET /health` — проверка.

## Правила

- Скелет по умолчанию, полное тело — только точечно. Никогда не вставляй
  целый файл в контекст, если есть скелет/фокус.
- Не выдумывай: все имена и числа в ответе обязаны быть в `skeleton`,
  `focus.context` или исходниках. Нет в источниках — так и скажи.
- Порог поиска: если лучший `score` > 1.5, явно скажи «релевантного не нашел»,
  вместо натяжки слабых чанков.
- Экономию считай как `saving_pct` из выдачи, сам не пересчитывай.
- Ограничения парсера: поле `code.parser` говорит, кто разобрал
  (`tree-sitter-java` — точно, `java-demo-regex` — грубо, возможны пропуски
  методов). Проза без кодовых имен в граф не попадает (нужен NER).

## Представление результата (ты оформляешь сам, сырые дампы не показываешь)

- Формат: заголовок (файл/класс, 1 строка сути) → 3–5 буллетов → компактная
  таблица методов (имя | что делает | связи) → экономия одной строкой.
- Каждое число — с единицей: «методов: 6», «вызовов addPacketCodec: 55».
  Голые агрегаты без единиц запрещены.
- Сырой JSON, полные скелеты и тела в ответ не вставлять — только выжимку.
  Детали (тело метода, полный список импортов) — по запросу пользователя.
- Сначала главное для задачи пользователя, метрики экономии — в конце.
