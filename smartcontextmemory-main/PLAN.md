# План снижения потери смысла (SCM Pro)

Цель: меньше токенов БЕЗ потери деталей, от которых зависит правильность.
Принцип: слоями (скелет → фокус → тело по требованию), каждая обрезка —
вслух с пометкой, что скрыто.

## Код

1. **Умные комменты.** Не резать `TODO/FIXME/WARNING/NOTE` и пояснения
   над сложными строками. Дешево, спасает предупреждения.
2. **Значения всегда в скелете.** Константы, дефолты параметров, аннотации
   (`@EventHandler`, лимиты) едут в LLM даже когда тело выкинуто.
3. **Писатели/читатели полей.** К соседям по вызовам добавить методы,
   трогающие те же поля, — ловит событийные связи (Bukkit-хендлеры),
   которых нет в графе вызовов.
4. **Контракты соседей.** Сигнатура + предусловия/возврат, извлеченные
   из тела (`if x == null return` → «требует не-null»). Ступень между
   скелетом и полным телом.
5. **Тело по требованию.** Модель должна иметь команду «дай тело X»,
   а не гадать по скелету (флешка уже в дизайне).

## Текст

6. **Якорь с контекстом.** Хранить предложение, где встретилась сущность
   («только когда все 5») — сохраняет условия почти бесплатно.
7. **Флаг отрицания.** Помечать чанки с «не/нет/only if» — ретривер
   различает факт и условие.
8. **Чанки по предложениям с нахлестом.** Сейчас рез по 800 символов
   рвет связи на границе чанка.
9. **Вес источникам.** Javadoc над методом > случайное упоминание.
   Приоритет якорей по месту, не только по имени.

## Общее

10. **Проверка ответом.** Все имена/числа из ответа модели обязаны
    найтись в исходниках — ловля галлюцинаций о деталях.
11. **Бенчмарк потерь.** Набор «вопрос → правильный кусок» на реальных
    файлах: recall ретривера + хватило ли контекста. Без него потери —
    ощущения, а не числа.

## Очередь (дешевое → дорогое)

1, 2 → 8 → 3, 6 → 4, 7 → 5 → 10 → 11.

## Статус реализации (2026-09-16, все 11 — done, 19/19 тестов)

- 1: `semantic_clean_code` сохраняет TODO/FIXME/WARNING/NOTE/XXX/HACK/BUG +
  пояснения над сложными строками + `# SMART:` из `/*...*/` (`scm_core.py`).
- 2: `_args_str` с реальными дефолтами, константы/поля со значениями,
  декораторы/аннотации в скелете; Java-поля с `value`, дерево показывает
  поля и `@`-теги (`scm_core.py:format_java_tree`).
- 3: `build_method_focus` добавляет `field_neighbors` (те же поля) +
  `call_neighbors`, в контексте помечены `[calls]/[field]` (`scm_core.py`).
- 4: `_extract_contract` (null/None-guard, requireNonNull, assert,
  throw/raise, предусловия) → `m['contract']`, видно в дереве и фокусе.
- 5: `extract_method_body` + `chat.py --get-body <имя> [--json]`
  (файл и индекс), `SKILL.md` шаг 3 — машинно, без просьб к пользователю.
- 6: `anchor_to_code(..., text)` → `context` (предложение-носитель) (`scm_core.py`).
- 7: `detect_negation` → `has_negation/negation_terms` в графе, метаданных
  FAISS, хитах `--once --json` и сервера; `[условие]` в консоли.
- 8: `split_prose_chunks/split_code_chunks` (нахлест 150 символов / 5 строк),
  `load_files` без O(N²) (счетчик вместо скана), `graph_v=2` → пересборка.
- 9: `_anchor_weight` (method 3.0 > class 2.5 > field 2.0 > partial 1.0),
  `suggest_focus` суммирует веса.
- 10: `verify_answer` + автовывод в `answer_once` (Ollama) и `serve.py /ask`
  (`verify`, `verify_text`), CLI `--verify/--against`.
- 11: `chat.py --bench [--json]` (recall@1/recall@k по методам/сущностям) +
  `tests/test_scm.py` (17 тестов, `python tests/test_scm.py`).
